MPS BENCHMARK: DIVISIBILITY AND SYMBOLIC EQUALITY FIXES

Environment: Apple M5 Mac, 24 GB RAM, AC power; macOS 27.2.1 arm64.
Native PyTorch 2.16.0a0+git6345ea6; FP32, contiguous inputs, inference only.
Commit: 6345ea65549d76751f09501580074b700b7c56c6
Parent compiler source: c79633996ebc2114482ae5a4ff3cb409d79a8a9c

Baseline: exact parent SizeVarAllocator.simplify method restored during compilation,
with guarded_shape_fusion=False. Fixed: both changes enabled. Both variants use
the same native 2.16 build; no native source differs between parent and fix.
Original team workload functions are imported unchanged (no shape-check branch).
Variants use separate callable code identities so both compiled graphs can stay
cached while timing alternates. Compiler changes are applied only during compilation.

METHOD
Two separate Python processes, different randomized case/compilation orders.
16 balanced, shuffled baseline-first/fixed-first pairs per case per process:
32 paired blocks per case in the summary. Fixed inputs and random seed per case.
Both variants are compiled and warmed before timing. MPS is synchronized before
and after each timed block. No input generation or compilation is included in
warm times, and graph counts are checked to reject recompilation in timed blocks.
All outputs were checked against eager at rtol=atol=1e-4: 80 comparisons passed.

Queued time: mean wall time per call in a repeated batch, then median over blocks.
This measures steady-state throughput including Python dispatch and allocations.
Repeats are calibrated and capped for memory; the same count is used for both sides.
Single-call latency: synchronize after every forward call; eight repetitions per
input sequence per block. It includes the synchronization/dispatch cost seen by
a caller waiting for each result. Neither timing is a GPU-kernel-only measurement.

95% intervals below resample paired timing blocks within each process (3000 draws).
They describe observed timing variation, not uncertainty over other machines or models.
Two fresh-process repeats agreed on the major improvements. No thermal or performance
warning was reported by pmset after the runs; other desktop activity was not controlled.

SHAPES
Split-head cases (B,T,C), H=8:
  small=(2,32,128), original=(2,512,512), large=(2,2048,2048).
Equality cases (M,Dx,Dy):
  small equal=(128,128,128), original equal=(4096,512,512), large equal=(4096,2048,2048).
  Unequal cases use Dy=1.5*Dx. No-split control uses (2,512,512).
Mixed stream repeats: (4096,512,512), (4096,512,768), (4096,256,256), (4096,512,768).

KERNELS AND GRAPH REUSE
All split-head cases: baseline two generated kernels, fixed one.
All equal-width cases: baseline two generated kernels, fixed one.
Unequal-width cases: two on both sides. No-split control: one on both sides.
Mixed stream: baseline one graph with two kernels; fixed two graphs, one with
one kernel and one with two. Both graph variants were warmed before timing.
These counts are generated kernel definitions, not profiler launch counts.

INTERPRETATION
At original sizes, split-head queued throughput improves 2.74-3.66x, while
synchronized single-call latency improves 1.75-1.83x. Equal widths improve
2.04x queued and 1.48x synchronized. Unequal widths are unchanged within noise.
Large split cases improve 3.35-4.10x in synchronized latency; large equality improves 1.69x.
Small-case synchronized gains are minor or noisy; do not generalize the large gains to tiny inputs.
The mixed stream improves 1.21x queued and 1.14x synchronized, but requires a
second graph: total setup is about 0.07s baseline versus 0.14s fixed here.
The speedups measure the full compiler changes, including altered indexing and
memory traffic. This experiment does not isolate kernel-launch count as the sole cause.
No training, BF16, CUDA, whole-model or application-level speedup is established.

ARTIFACTS
bench.py: reproducible measurement harness. summarize.py/report.py: analysis.
run1/results.json and run2/results.json: all raw timings and setup measurements.
run1/code and run2/code: generated wrappers/kernels for every compiled graph.
summary.json: medians, per-run speedups, paired bootstrap intervals.
pilot results are excluded from the final analysis.
